# Project Context

## Purpose

This repository is a public, language-agnostic open-source foundation. Replace this template framing with the actual user problem, public value, and intended outcome during initialization.

## Users

Name users, contributors, integrators, and maintainers, plus the decisions each group needs to make.

## Domain Language

Define project-specific terms only after they have a stable meaning. Prefer one term per concept.

## Constraints

- Choose a framework, runtime, database, and deployment target only when a real milestone requires them.
- External accounts, production access, and secret sources are explicit human gates.
- The project declares taxonomy intent locally but does not register itself globally.
- Public API, compatibility, support, security-response, and release promises must be explicit and evidence-backed.

## Non-goals

- Framework or vendor lock-in before requirements exist
- Automatic taxonomy mutation
- Enabled connectors or deployment defaults
- Unfunded service-level or support promises
- Private operational details or secret-bearing examples
