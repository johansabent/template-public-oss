# Contributing

Thank you for helping improve the project.

## Before You Start

- Search existing issues and pull requests.
- Use a structured issue for bugs or feature proposals.
- Keep security reports out of public issues; follow `SECURITY.md`.
- For a generated repository, finish project initialization and confirm `onboarding / validate` succeeds before implementation work.

## Changes

1. Keep each change focused on one problem.
2. Add or update tests for changed behavior.
3. Update documentation when behavior or public interfaces change.
4. Run the repository's documented validation commands.
5. Explain the problem, approach, evidence, and residual risk in the pull request.
